## Connective Tissue (Integration Map)

The remaining gaps, ordered by how much each one hurts a user trying to *use* the kernel today:

1. **No unified `production` dispatcher.** Pain: with four sibling CLIs on disk (`timeline`, `trace`, `doctor`, `compare`) a user must remember four different `python -m src.cli.<name>` incantations and the per-tool flag shape. There is no `production --help`, no `production compare`, no `pyproject.toml [project.scripts]` entry. The `src/cli/__init__.py` docstring itself lists the gap.
2. **No top-level `production run "<intent>"`.** Pain: the project's headline promise ("give it an intent, get a production") is demonstrated only by `python -m src.demo_flow`, which is one-shot and synthetic. A new user cannot reproduce the demo without reading source.
3. **No runner drives the 26-stage pipeline.** Pain: the state machine is in code (`_ALLOWED_TRANSITIONS`); nothing walks it. Every demo path is bespoke (`scripts/run_demo.py`, `examples/run_crew_demo.py`, `src/demo_flow.py`). Tied to the keystone above.
4. **No end-to-end happy-path test.** Pain: `python -m src.demo_flow` runs; nothing asserts every gate fires, every agent produces output, and the publish manifest validates.
5. **Plugin registry is not auto-discovered.** Pain: the kernel-blind claim is unobservable — adding a vertical today means editing kernel code, not dropping a folder.
6. **Web surface is 2 of 5 wireframes.** Pain: Timeline view and Director's Canvas (the two highest-wonder views) remain SVG-only — the audit trail and proposal-comparison flow are invisible in the browser.
7. **Asset lineage is data, not a UI.** Pain: `production trace` reads the asset DAG; nothing in `web/` renders it.
