## Connective Tissue — where the system leaks

These are the seams that keep the project feeling like a library rather than a product. Each is unchanged from the morning audit **except #2**, which is now closed.

1. **No runner drives the 26-stage pipeline.** State machine is in code; nothing walks it. Pain: every demo path is bespoke (`scripts/run_demo.py`, `examples/run_crew_demo.py`, `src/demo_flow.py`); a new user does not know which script to run.
2. **~~Audit trail was data, not UI.~~ DONE.** `python -m src.cli.timeline <prod_id>` now renders gate decisions, state transitions, and snapshots as a readable timeline. `--summary` and `--json` modes included.
3. **No unified `production` CLI.** Subcommands are `python -m src.cli.<name>`; no top-level `production run | timeline | trace | doctor | compare` entry. Pain: each new CLI command requires explaining the long form.
4. **No top-level `production run "<intent>"`.** Pain: the project's headline promise ("give it an intent, get a production") is demonstrated only by `demo_flow.py`, which is one-shot and synthetic.
5. **Asset lineage is recorded but not queryable.** Pain: a `Reference` carries `sha256`, `GenerationResult` carries `output_sha256`, `VersionSnapshot` carries `content_hash` — but no command answers "where did this asset come from and where did it go?"
6. **Plugin registry is not auto-discovered.** Pain: the kernel's plugin-blind claim is unobservable — to add a vertical today you edit kernel code.
7. **Web surface is 2 of 5 wireframes.** Pain: `Timeline view` and `Directors Canvas` are the two missing high-wonder views; their absence makes the audit trail and proposal-comparison flow invisible in the browser.
8. **End-to-end happy path is not test-protected.** Pain: `python -m src.demo_flow` runs; nothing asserts that every gate fires, every agent produces output, and the publish manifest validates.
