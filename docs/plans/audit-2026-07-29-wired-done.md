## TL;DR

Open Production is now **end-to-end runnable from a single command on every shell incantation
it advertises.** `run` is wired into the dispatcher (`src/cli/__main__.py` imports `run`,
`_SUBCOMMAND_HELP` and `_COMMAND_MAINS` both contain `run`, and a new `run_parser` mirrors
`src/cli/run.py`'s argparse verbatim), so `python -m src.cli run "X" --no-confirm --out <dir>`
and `python -m src.cli.run "X" --no-confirm --out <dir>` are now functionally identical, and
the `production run` console-script form resolves the same way via the entry-point chain in
`pyproject.toml`. The change is locked by three new tests in `tests/test_cli_main.py`
(`test_run_help_exits_zero_and_mentions_topic_and_no_confirm`,
`test_run_delegates_and_creates_production_json`,
`test_production_console_script_run_help_exits_zero`) — the file now has 10 tests, all green
(combined with `tests/test_cli_run.py`'s 7 tests, the run + dispatcher pair is 17/17 green).
The integration story has shrunk to **web**: the kernel + service + state-machine + CLI +
audit trail are all wired, but only 2 of 5 wireframe views exist on disk (`GuidedFlow` +
`AgentConsole`). The remaining high-wonder gap is the **Director's Canvas (Timeline view)**,
which is the next smallest lift that surfaces the audit trail in the browser — and the one
artifact the demo video needs most.

## Connective Tissue — where the system leaks

The CLI surface is closed; the remaining seams are higher in the stack:

1. **Web is 2 of 5 wireframes.** Pain: `production timeline` and `production trace` are real CLI surfaces that read the audit trail and asset DAG as readable text, but the Timeline view (wireframe 03), Director's Canvas (01), and Node Graph (05) are SVG-only. A judge clicking into the web app sees only the guided-flow chat surface; the two highest-wonder kernel properties (audit trail, proposal divergence) are invisible in the browser. The Director's Canvas in particular is the canvas the spec at `docs/principles.md` calls "the single window into every creative decision" — without it, the web demo can't show a producer the state of a production the way `production doctor` shows it on the terminal.
2. **Audit trail is data + terminal text, not a UI.** Pain: `audit.jsonl` is appended by `ProductionService.apply_event`; `production timeline` renders it as a table; `AuditEntryRow.tsx` exists in the web bundle but no view surfaces it as the primary surface. The Director's Canvas is the natural home.
3. **Asset lineage is CLI-readable, not browsable.** Pain: same shape as #2 but for `production trace`. Even modest Mermaid rendering on a web view would let the user click into the proposal-first loop.
4. **Plugin registry is not auto-discovered.** Pain: the kernel-blind claim is still unobservable — adding a vertical today means editing kernel code.
5. **The dispatcher's test does not enforce the full surface beyond the four siblings.** Pain: partially closed — `test_no_args_lists_all_subcommands` now includes the `run` line and `test_run_help_exits_zero_and_mentions_topic_and_no_confirm` asserts the new flags, but if a sixth subcommand is added later, only `_run_cli()` (the bare-invocation usage block) will catch a regression. Worth a follow-up: assert each subcommand is in `_COMMAND_MAINS` directly.
6. **End-to-end happy path is test-protected but not LLM-fixtured.** Pain: `test_cli_run.py` runs the whole pipeline with `MockLLMClient`; no recorded LLM trace exists. Incremental.
7. **No `production plan-status`.** Pain: this audit was hand-written.
