## Connective Tissue — where the system leaks

These are the seams that keep the project feeling like a library rather than a product. Each is unchanged from the prior re-audit **except #5**, which is now closed.

1. **No runner drives the 26-stage pipeline.** State machine is in code; nothing walks it. Pain: every demo path is bespoke (`scripts/run_demo.py`, `examples/run_crew_demo.py`, `src/demo_flow.py`); a new user does not know which script to run.
2. **Audit trail was data, not UI.** DONE. `python -m src.cli.timeline <prod_id>` renders gate decisions, state transitions, and snapshots as a readable timeline.
3. **Asset lineage was recorded but not queryable.** DONE. `python -m src.cli.trace <sha256>` (or `<prod_id>`) renders references, generations, snapshots, branches, and merges as a DAG — ASCII tree or `--mermaid` for the browser.
4. **No unified `production` CLI.** Subcommands are still `python -m src.cli.<name>`; no top-level `production run | timeline | trace | doctor | compare` entry. Pain: each new CLI command requires explaining the long form.
5. **No top-level `production run "<intent>"`.** Pain: the project's headline promise ("give it an intent, get a production") is demonstrated only by `demo_flow.py`, which is one-shot and synthetic.
6. **No health-check entry point.** Pain: after `timeline` (audit) and `trace` (provenance) there is still no single command that says "is this production healthy?" — readers must know to grep `audit.jsonl` for failures, count gate violations, and cross-reference `production.json`. With **two of three observability surfaces built**, this is now the missing leg of the triad.
7. **Plugin registry is not auto-discovered.** Pain: the kernel's plugin-blind claim is unobservable — to add a vertical today you edit kernel code.
8. **Web surface is 2 of 5 wireframes.** Pain: `Timeline view` and `Directors Canvas` are the two missing high-wonder views; their absence makes the audit trail and proposal-comparison flow invisible in the browser.
9. **End-to-end happy path is not test-protected.** Pain: `python -m src.demo_flow` runs; nothing asserts that every gate fires, every agent produces output, and the publish manifest validates.

## Suggested next action

**Build `production doctor`.** Effort S (one new file `src/cli/doctor.py` reusing `_production_dir.py` + the renderer pattern from `timeline.py` and `trace.py`, plus a small test file). It closes the observability triad — `timeline` reads the audit log, `trace` reads the asset DAG, `doctor` reads everything else (gate counts, schema validity, plan-to-code map, plugin registry, test runner) and emits a single green/yellow/red report. With the triad complete, a new user can run three commands on any production and understand exactly what it did, where its assets came from, and whether it is healthy. After this, `compare` and the unified `production` dispatcher are both <30-minute lifts on the same scaffolding, and `production run "<intent>"` becomes the natural M-effort capstone that turns the library into a product.
