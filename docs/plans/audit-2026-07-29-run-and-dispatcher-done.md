## TL;DR

Open Production is now **end-to-end runnable from the terminal on two equivalent
incantations, but only one of them knows about `run`.** `python -m src.cli.run
"<intent>"` works on its own (`src/cli/run.py`, 6.8 KB, mirrors the renderer
pattern of timeline/trace/doctor/compare, ANSI-coloured, `--no-confirm` /
`--pick`, calls `PipelineRunner().run(intent, out_dir)`), locked by
`tests/test_cli_run.py` (10.6 KB; happy path + idempotent re-run + empty-
proposal tolerance + schema validation). The unified `production` dispatcher is
also real: `src/cli/__main__.py` (8.6 KB, `argparse.subparsers` fanning out to
`timeline` / `trace` / `doctor` / `compare`), `src/cli/__init__.py` now exports
`main`, and `pyproject.toml` ships `[project.scripts] production =
"src.cli.__main__:main"`. **But `run` is missing from both `_SUBCOMMAND_HELP`
and `_COMMAND_MAINS` in `src/cli/__main__.py`**, and `tests/test_cli_main.py`
does not assert its presence — so `production run "<intent>"` (the short form)
and `python -m src.cli run "<intent>"` (the module form) both still fail with
"unknown subcommand: run". The single next feature is to close that wire.

## Connective Tissue — where the system leaks

The integration story shrank again but did not close:

1. **`run` is not registered in the dispatcher.** Pain: today `production
   timeline` / `production trace` / `production doctor` / `production compare`
   all work through the short form, but the keystone headline command
   `production run "<intent>"` does not. The two halves of the "you can drive
   Open Production end-to-end from one command" promise were built in
   parallel, and the seam between them is one missing line in
   `_COMMAND_MAINS` plus one missing `argparse` subparser. `src/cli/__init__.py`
   even lists `run` in its own module docstring as a registered subcommand —
   the docstring lies about the current state.
2. **The dispatcher's test does not enforce the full surface.** Pain:
   `tests/test_cli_main.py` asserts only the four sibling CLIs; if a fifth
   subcommand (or sixth, or seventh) is added later, the test will not catch
   a regression in `--help` listing. This is why gap #1 is silent.
3. **No runner for the missing stages 23–26.** Pain: 22 of 26 stages are
   wired through `demo_flow.run_pipeline`; the four unwired stages are
   bookkeeping (assembly, asset-library finalization, export, archive) and
   their absence is observable only in the audit log. Lower priority than #1.
4. **Asset lineage is recorded and CLI-readable, but not a web UI.** Pain:
   `production trace` reads the asset DAG; nothing in `web/` renders it. Same
   gap as yesterday.
5. **Plugin registry is not auto-discovered.** Pain: the kernel-blind claim
   is still unobservable — adding a vertical means editing kernel code.
6. **Web surface is 2 of 5 wireframes.** Pain: Timeline view and Director's
   Canvas remain SVG-only.
7. **No `production plan-status`.** Pain: this audit was hand-written; nothing
   in the kernel automates plan ↔ code diffing.
